MA 252 Regression Analysis·May 2026·Rmultiple regressioninteraction terms

What drives post-college earnings?

Using a random sample of 1,000 institutions from the U.S. Department of Education's College Scorecard, we modeled graduates' median earnings ten years after entry from SAT average, net price, school type and school size. We tested four models, including interactions between selectivity, cost and institution type.

The payoff for academic selectivity depends on school size. Each SAT point is worth $52 in earnings at small schools, $79 at medium schools and $71 at large schools. The final model explains 52.45% of the variation in earnings (adjusted R²).

  • Rejected interactions that did not hold up. SAT × school type and net price × school type were not significant and left adjusted R² essentially unchanged (0.514), so they stayed out of the final model.
  • Kept earnings untransformed. A log transform was slightly more normal, but it would have made the dollar interpretation less clear for readers.

My role: Team project with Nathania Kwik. I handled data cleaning, exploratory data analysis, interpretation of the base model, and the presentation slides.

Finding unsatisfied customers, priced in dollars

I built classifiers to predict which retail customers are unsatisfied with AI-driven shopping experiences. I compared KNN, logistic regression, SVM, decision trees, random forests and Naive Bayes. Then I chose a model by business value instead of accuracy: catching an unsatisfied customer was worth $5,000, and a false alarm cost $500.

Logistic regression with class weights had the highest net benefit, $68,500, with 66.67% recall. It beat a random forest that had slightly higher accuracy, because it caught more of the customers who mattered.

  • Treated "Unsatisfied" as the positive class, because missing an unhappy customer costs the business more than a false alarm.
  • One-hot encoded categorical features. Scaled features for the distance-based models (KNN, SVM, logistic regression) and left the tree-based models unscaled.
  • Used a stratified 80/20 train-test split with a fixed random seed, so the results can be reproduced.

National Park Service schema

A database for park staffing and visitor counts. Employees work at many parks through an associative entity (EmployeePark) that records weekly hours. Visitation is a weak entity, with one row per park per year.

  • All four tables and the sample data load cleanly in MySQL.
  • Revised: the original script left out the foreign keys drawn in the ERD, so it accepted a work shift for an employee who didn't exist. Those inserts are now rejected (error 1452).
  • Added a labor-cost query. Result: Acadia $1,415/week across 2 staff, Boston Harbor Islands $450, Cape Cod $435.
-- Syla Cintron
-- CS 160 – Data Driven Decision Making
-- National Park Service: relational schema (MySQL)
-- Revised: added the foreign keys shown in the ERD so the database
-- rejects staffing or visitation rows for parks/employees that don't exist.

DROP TABLE IF EXISTS Visitation;
DROP TABLE IF EXISTS EmployeePark;
DROP TABLE IF EXISTS Park;
DROP TABLE IF EXISTS Employee;

CREATE TABLE Employee (
    EmployeeID   INT,
    Name         VARCHAR(100) NOT NULL,
    Age          INT,
    StartDate    DATE,
    JobTitle     VARCHAR(100),
    HourlyRate   DECIMAL(5,2),
    PRIMARY KEY (EmployeeID)
);

CREATE TABLE Park (
    ParkNumber    INT,
    ParkName      VARCHAR(100) NOT NULL,
    ParkAddress   VARCHAR(300),
    ParkCategory  VARCHAR(100),
    PRIMARY KEY (ParkNumber)
);

-- Associative entity: an employee can work at many parks, a park has many employees
CREATE TABLE EmployeePark (
    EmployeeID    INT,
    ParkNumber    INT,
    HoursPerWeek  INT,
    PRIMARY KEY (EmployeeID, ParkNumber),
    FOREIGN KEY (EmployeeID) REFERENCES Employee (EmployeeID),
    FOREIGN KEY (ParkNumber) REFERENCES Park (ParkNumber)
);

-- Weak entity: one visitor count per park per year
CREATE TABLE Visitation (
    ParkNumber     INT,
    Year           YEAR,
    NumOfVisitors  INT,
    PRIMARY KEY (ParkNumber, Year),
    FOREIGN KEY (ParkNumber) REFERENCES Park (ParkNumber)
);

-- Weekly labor cost per park
SELECT p.ParkName,
       COUNT(ep.EmployeeID)                     AS Staff,
       SUM(ep.HoursPerWeek * e.HourlyRate)      AS WeeklyLaborCost
FROM Park p
JOIN EmployeePark ep ON ep.ParkNumber = p.ParkNumber
JOIN Employee e      ON e.EmployeeID  = ep.EmployeeID
GROUP BY p.ParkName
ORDER BY WeeklyLaborCost DESC;

Fitness studio supertype/subtype

An enhanced ERD carried into Oracle SQL. FitnessClass is the supertype with shared attributes. YogaClass and CyclingClass are subtypes with their own attributes, and members register for classes through ClassRegistration.

  • All five tables, sample data and the summary query run cleanly.
  • Revised: subtypes are now disjoint. Each subtype references (ClassID, ClassType), so a cycling class can't also be stored as a yoga class. That insert is now rejected.
  • Added CHECK constraints for the class type ('Yoga' or 'Cycling') and the Heated flag ('TRUE' or 'FALSE'). An unknown class type is rejected.
  • Registrations for members who don't exist are rejected by the foreign key.
-- Syla Cintron
-- CS 350 – Database Management
-- Fitness studio: supertype/subtype (EERD) implementation (Oracle SQL)
-- Revised: ClassType is now checked, and each subtype table references
-- (ClassID, ClassType), so a class can only be a Yoga OR a Cycling class
-- (disjoint subtypes), matching its type in FitnessClass.

DROP TABLE ClassRegistration CASCADE CONSTRAINTS;
DROP TABLE YogaClass CASCADE CONSTRAINTS;
DROP TABLE CyclingClass CASCADE CONSTRAINTS;
DROP TABLE FitnessClass CASCADE CONSTRAINTS;
DROP TABLE Member CASCADE CONSTRAINTS;

CREATE TABLE Member (
    MemberID        NUMBER,
    FirstName       VARCHAR2(100) NOT NULL,
    LastName        VARCHAR2(100) NOT NULL,
    Email           VARCHAR2(150),
    MembershipType  VARCHAR2(50),
    CONSTRAINT pk_member PRIMARY KEY (MemberID)
);

-- Supertype
CREATE TABLE FitnessClass (
    ClassID          NUMBER,
    ClassName        VARCHAR2(100) NOT NULL,
    ClassType        VARCHAR2(50)  NOT NULL,   -- subtype discriminator
    Duration         NUMBER,
    DifficultyLevel  VARCHAR2(50),
    InstructorName   VARCHAR2(100),
    CONSTRAINT pk_fitness_class PRIMARY KEY (ClassID),
    CONSTRAINT ck_class_type CHECK (ClassType IN ('Yoga', 'Cycling')),
    CONSTRAINT uq_class_id_type UNIQUE (ClassID, ClassType)
);

-- Subtype: yoga
CREATE TABLE YogaClass (
    ClassID          NUMBER,
    ClassType        VARCHAR2(50) DEFAULT 'Yoga' NOT NULL,
    YogaStyle        VARCHAR2(100),
    Heated           VARCHAR2(5),
    EquipmentNeeded  VARCHAR2(200),
    IntensityLevel   VARCHAR2(50),
    CONSTRAINT pk_yoga_class PRIMARY KEY (ClassID),
    CONSTRAINT ck_yoga_type CHECK (ClassType = 'Yoga'),
    CONSTRAINT ck_yoga_heated CHECK (Heated IN ('TRUE', 'FALSE')),
    CONSTRAINT fk_yoga_fitness FOREIGN KEY (ClassID, ClassType)
        REFERENCES FitnessClass (ClassID, ClassType)
);

-- Subtype: cycling
CREATE TABLE CyclingClass (
    ClassID          NUMBER,
    ClassType        VARCHAR2(50) DEFAULT 'Cycling' NOT NULL,
    BikeType         VARCHAR2(100),
    ResistanceLevel  NUMBER,
    MusicTheme       VARCHAR2(100),
    TargetDistance   NUMBER(10,2),
    CONSTRAINT pk_cycling_class PRIMARY KEY (ClassID),
    CONSTRAINT ck_cycling_type CHECK (ClassType = 'Cycling'),
    CONSTRAINT fk_cycling_fitness FOREIGN KEY (ClassID, ClassType)
        REFERENCES FitnessClass (ClassID, ClassType)
);

-- Associative entity: members register for many classes
CREATE TABLE ClassRegistration (
    MemberID          NUMBER,
    ClassID           NUMBER,
    RegistrationDate  DATE,
    AttendanceStatus  VARCHAR2(50),
    CONSTRAINT pk_class_registration PRIMARY KEY (MemberID, ClassID),
    CONSTRAINT fk_registration_member FOREIGN KEY (MemberID) REFERENCES Member (MemberID),
    CONSTRAINT fk_registration_class  FOREIGN KEY (ClassID)  REFERENCES FitnessClass (ClassID)
);

       y.YogaStyle, c.BikeType, c.TargetDistance

Department store business questions

Seven questions answered against a store database of items, suppliers, deliveries, departments and employees. The queries use filtering, pattern matching, a three-table join, and aggregation with GROUP BY and HAVING.

  • All seven queries run and return correct results on the course database.
  • Revised for readability: table aliases, named result columns, rounded averages, and department names that match the stored values exactly, so the queries also work on databases that compare text case-sensitively.
-- Syla Cintron
-- CS 160 – Individual SQL assignment: department store database (MySQL)
-- Revised for readability: column aliases, rounded averages, and
-- department names written exactly as stored.

-- 1. Which item types does the store sell?
SELECT DISTINCT itemtype
FROM items_for_sale;

-- 2. Which deliveries went to the Equipment department?
SELECT delivery_no
FROM store_delivery
WHERE deptname = 'Equipment';

-- 3. Which suppliers are manufacturers?
SELECT *
FROM store_suppliers
WHERE supplier_name LIKE '%Manufacturing%';

-- 4. How many people work in Marketing?
SELECT COUNT(*) AS marketing_headcount
FROM store_employees
WHERE deptname = 'Marketing';

-- 5. Which items are supplied by All Sports Manufacturing?
SELECT DISTINCT i.itemname
FROM store_suppliers s
JOIN store_delivery d ON s.supplier_no = d.supplier_no
JOIN items_for_sale i ON d.itemname    = i.itemname
WHERE s.supplier_name = 'All Sports Manufacturing';

-- 6. Which department phone should be called about each delivered item?
SELECT d.itemname, dep.deptphone
FROM store_delivery d
JOIN store_departments dep ON d.deptname = dep.deptname
ORDER BY d.itemname;

-- 7. Which departments average under $32,000 in salary?
SELECT deptname, ROUND(AVG(empsalary), 2) AS avg_salary
FROM store_employees
GROUP BY deptname
HAVING AVG(empsalary) < 32000
ORDER BY avg_salary DESC;
